## Part 4 — proposed ADRs

Titles only. Use the `adr` skill to author any of these if you decide they're worth recording.

- **PLAN.md cluster naming contract** — cluster descriptions referencing external content must cite verbatim slugs from a previously-fetched index page with URL. Grounded in three consecutive slug-paraphrase failures.
- **Repeat-fanout branch naming convention** — `<feature>--rN-sub-NN` when prior `--sub-NN` names exist on origin. Grounded in Round 4's name-collision avoidance.
- **Per-fanout state-discipline contract** — every fanout run produces `harness/runs/<run_id>/{state.json, plan.yaml, report.md}`. Grounded in 3 consecutive rounds applying this pattern.
- **Probe-then-body fetch pattern as default** — when external slugs are not authoritatively known, the fetch flow is two issues, not one. Grounded in Round 4's generalization of Round 3's lesson.
- **SPA silent-404 detection contract** — fetched responses with <8 KB body containing only navigation skeleton are 404s in disguise; either the fetch script flags them in the per-URL summary or the drain step manually inspects byte counts. Grounded in Round 5 issue #21.
- **Layer-0 outer-harness audit step before Core-Four diagnostic tree** — when debugging an agent run, the first audit target is AgentConfig load + trigger payload assembly + claude launch args, *before* prompt/model/context/tools. Grounded in report 08's Raschka citation.
- **LESSONS.md curation contract** — adopt the `[<prefix-NNNNN>] helpful=N harmful=M *[YYYY-MM-DD]*:: <assertion>` line format with category prefixes (`res-`, `ver-`, `ctx-`, `tri-`, `oau-`, `gat-`, `obs-`, `mcp-`, `sec-`) and the PRESERVE/APPEND/DATE/REMOVE update rules. Grounded in report 08 §4 + report 06 §10 + report 11 §2.2.
- **Port `get_authenticated_git_url` verbatim from OpenHands when adding 2nd provider (Stage 4)** — Azure DevOps and Bitbucket DC URL conventions are non-rederivable from upstream docs. Grounded in report 05 §4.
- **`_paginate(url, max, ...) -> list[dict]` Protocol shape for Stage 4 ProviderClient** — GitHub-style `Link: rel="next"` as the default (covers GitHub + GitLab + Forgejo); override for Bitbucket Cloud (body-field `next` URL); override for Azure DevOps (no cursor, client-side slice). Grounded in report 10 §"Recommended Protocol".
- **GitHub MCP scope is `lago-morph/agent-runner` only — cross-repo reads go through WebFetch** — promote the runtime-discovered scope policy into a project-level constraint. Grounded in Round 3 sub-03 fallback.
